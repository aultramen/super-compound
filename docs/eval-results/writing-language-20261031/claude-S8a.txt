`/sc-status` は**読み取り専用の状況確認ワークフロー**です。セッション開始時や、現在の位置がわからないときに使います。定義は `.agent/workflows/sc-status.md` にあります。

**確認する項目**
1. 引き継ぎファイル `.continue-here.md`
2. `docs/STATE.md` と `docs/progress.md`。`docs/STATE.md` が正式な現在位置です。ただし、その内容は `git status` と照合します。
3. `.scratch/*/issues/` の issue メタデータ（`Status`、`Goal ID`、`Blocked by`）。本文は読みません。
4. Git の状態（branch、upstream、worktree）。Git は変更しません。
5. `node .agent/tools/memory-maintenance.mjs report` の結果
6. 保存済みの完了証跡。メタデータや空のキューだけでは「成功」と判断しません。テストの再実行もしません。

**出力**
- 短いダッシュボード：現在位置、完了した作業、残りの作業、ブロッカー、issue の状況、検証の状況
- 次に実行するワークフローを **1つだけ** 推奨します（例：`/sc-work`、`/sc-debug`、`/sc-plan`）。
- 推奨と一緒に、delivery tier も示します。
  - `light`：`/sc-work` または `/sc-debug` に直接進みます。
  - `full`：既存の成果物に応じて `/sc-explore`、`/sc-prd`、`/sc-plan` に進みます。

**原則**
- ファイル、memory、Git には何も書き込みません。
- 承認済みの作業が進行中の場合は、ユーザーにコマンドを再入力させません。担当のワークフローに処理を戻して、作業を続けます。
